# Markdown Imports Autogen — Specification

## 1. Purpose

Automatically generate `.gen.ts` files that map markdown documentation paths to their
TypeScript `import(... ?raw)` expressions. These files are consumed by Astro pages
( e.g. `src/pages/docs/[doc].astro`) to provide static import content for
`getStaticPaths` routing.

The tool enforces a structural invariant on the markdown directory tree:

> **Every directory (and subdirectory) that contains at least one `.md` file as a
> direct child must contain exactly one. Directories with zero `.md` files are
> permitted and ignored.**

---

## 2. Current State

### 2.1 Seed mapping (`autoGenerated` record)

Defined in `src/tools/markdown-imports-autogen/markdown-import-autogen.ts`:

```ts
export const autoGenerated: Record<string, string> = {
	'src/autogen/docs.gen.ts': '/resources/docs',
}
```

Key = auto-generated file path (repo-root-relative, with leading `/`).
Value = source directory to scan (repo-root-relative).

### 2.2 Target output file (`src/autogen/docs.gen.ts`)

```ts
const markdownFiles: Record<`/${string}.md`, string> = {
	'/resources/docs/features/features.md': (
		await import('@/resources/docs/features/features.md?raw')
	).default,
}

export default markdownFiles
```

### 2.3 Consumer (`src/pages/docs/[doc].astro`)

- Imports `markdownFiles` from `./docs.gen`
- Iterates `Object.keys(markdownFiles)` to produce `getStaticPaths` entries
- Looks up content by resolved path key

---

## 3. Output File Format

The generated file must be a **valid TypeScript module** that:

1. Declares a `const markdownFiles: Record<\`/${string}.md\`, string>` object
2. Has one entry per eligible `.md` file
3. Each entry key is the **repo-root-relative path with a leading `/`**
   (e .g. `'/resources/docs/features/features.md'`)
4. Each entry value is `await import('@/resources/docs/...?raw').default`
   — the import path uses the `@/` alias mapping
5. `export default markdownFiles` at the end
6. Is formatted with **Prettier** (`parser: 'typescript'`) using the project's config
7. Has a brief auto-generated comment at the top

### 3.1 Path alias conversion

| Repo-root-relative path | Import path                   |
| ----------------------- | ----------------------------- |
| `resources/docs/foo.md` | `@/resources/docs/foo.md?raw` |
| `src/pages/docs/bar.md` | `@/src/pages/docs/bar.md?raw` |

Rule: prepend `@` to the path, append `?raw`.

---

## 4. Directory Scanning Rules

### 4.1 Eligibility of a markdown file

A `.md` file is eligible for inclusion **if and only if**:

- It is a **direct child** of some directory within (or at) the configured source dir
- That parent directory contains **exactly one** `.md` file as a direct child

### 4.2 Error conditions

A directory containing **two or more** `.md` files as direct children is an error.
The tool must report:

- The directory path
- The names of all offending `.md` files

### 4.3 Allowed conditions

- Directories with **zero** `.md` files — silently skipped
- Non-`.md` files (images, etc.) in the same directory — ignored for counting purposes
- Arbitrary nesting depth — each directory evaluated independently

### 4.4 Concrete example (current `resources/docs` tree)

```
resources/docs/
├── contribute/                          → 0 .md files → OK (skip)
│   ├── images/                          → 0 .md files → OK (skip)
│   ├── ui/ui.md                         → 1 .md file → ELIGIBLE
│   └── wallet-data/wallet-data.md       → 1 .md file → ELIGIBLE

│   └── software-wallet-questionnaire.md → 1 .md file → ELIGIBLE
└── wallet-testing/                      → 0 .md files → OK (skip)
    ├── chain-verification/
    │   └── chain-verification.md        → 1 .md file → ELIGIBLE
```

## 5. Architecture

Two files:

| File                             | Role                                     |
| -------------------------------- | ---------------------------------------- |
| `markdown-import-autogen-lib.ts` | Core library (class, exported for tests) |

### 5.1 `markdown-import-autogen-lib.ts` — Class: `MarkdownImportsGenerator`

```ts
import * as fs from 'node:fs'
import * as path from 'node:path'

import * as prettier from 'prettier'
import { getRepositoryRoot } from '@/tests/utils/codebase'
import { trimWhitespacePrefix } from '@/types/utils/text'

export interface MarkdownImportsConfig {
	/** Absolute path to the generated .gen.ts file */
	genFilePath: string
	/** Absolute paths to source directories to scan */
	sourceDirs: string[]
}

export class MarkdownImportsGenerator {
	private readonly repoRoot: string
	private readonly genFilePath: string
	private readonly sourceDirs: string[]

	constructor(config: MarkdownImportsConfig)

	/**
	 * Recursively walk all sourceDirs and return a Map of
	 * absolute directory path → list of direct-child .md file names.
	 */
	private scanDirectories(): Map<string, string[]>

	/**
	 * Validate the "exactly one .md per directory" rule.
	 * Returns an array of human-readable error strings.
	 * Empty array means no errors.
	 */
	public validate(): string[]

	/**
	 * Returns sorted array of repo-root-relative paths (with leading '/')
	 * for all eligible .md files.
	 */
	public getEligibleFiles(): string[]

	/**
	 * Generates the full source code of the .gen.ts file as a string.
	 * Does NOT pass through Prettier — caller does that for write.
	 */
	public generateContent(): string

	/**
	 * Generates the Prettier-formatted .gen.ts file content.
	 */
	public generateFormatted(): Promise<string>

	/**
	 * Returns true if the file on disk matches the formatted generated content.
	 * Returns false if the file does not exist.
	 */
	public isUpToDate(): boolean

	/**
	 * Writes the formatted content to disk.
	 * Creates parent directories if needed.
	 * Does NOT write if content is identical to what's already on disk (idempotent).
	 */
	public write(): Promise<void>

	/**
	 * Returns a shell command string that can re-run this generator in write mode.
	 * e.g. 'pnpm tsx src/tools/markdown-imports-autogen/markdown-import-autogen.ts --mode write'
	 */
	public writeCommand(): string

	/**
	 * Returns the repo-root-relative path of the generated file (with leading '/').
	 */
	public genFileRelativePath(): string
}
```

### 5.2 `markdown-import-autogen.ts` — CLI entry point

```
Usage: pnpm tsx src/tools/markdown-imports-autogen/markdown-import-autogen.ts --mode <mode>

Options:
  --mode <mode>    "check" or "write"  (required)
  --help           Show this help text
```

- `--mode check`: validate all source dirs + compare generated vs on-disk.
  Exit code 0 if clean, exit code 1 if validation errors or out of date.
- `--mode write`: validate all source dirs + write regenerated files.
  Exit code 0 on success, exit code 1 if validation errors.

Both modes iterate over **all entries** in `autoGenerated` and operate on each.

## 6. Internal Implementation Details

### 6.1 `scanDirectories()`

- For each `sourceDir`, use `fs.readdirSync(dir, { withFileTypes: true })`
- Recurse into subdirectories
- For each directory encountered (including the root source dir itself), count
  the direct children whose names end with `.md`
- Accumulate into `Map<string, string[]>` (absolute dir path → [md filenames])

### 6.2 `validate()`

- Iterate every entry in the scan map
- If a directory has `entries.length > 1`, produce an error string:
  ```
  <dir>: Found N .md files, expected exactly 1: file1.md, file2.md, ...
  ```
- Return all errors collected

### 6.3 `getEligibleFiles()`

- From the scan map, collect the single `.md` file path for every directory
  with exactly 1 entry
- Convert each to a repo-root-relative path with leading `/`
- Sort alphabetically
- Return

### 6.4 `generateContent()`

Build the raw TypeScript source (before Prettier):

```ts
private generateContent(): string {
  const files = this.getEligibleFiles()
  const entries = files
    .map(mdPath => {
      const importPath = mdPath
        .replace(/^\/resources\//, '@/resources/')
        .replace(/^\/src\//, '@/src/')
        .replace(/^\//, '@/')
      return `    '${mdPath}': (await import('${importPath}?raw')).default,`
    })
    .join('\n')

  return trimWhitespacePrefix(`
    /**
     * Auto-generated import mappings for markdown documentation files.
     * DO NOT edit manually — run the markdown-imports-autogen tool to regenerate.
     */
    const markdownFiles: Record<`/${string}.md`, string> = {
    ${entries}
    }

    export default markdownFiles
  `) + '\n'
}
```

When `files` is empty, the object body is empty (`{}`).

### 6.5 `generateFormatted()`

```ts
async generateFormatted(): Promise<string> {
  const raw = this.generateContent()
  const prettierConfig = (await prettier.resolveConfig(this.genFilePath)) ?? {}
  return prettier.format(raw, { ...prettierConfig, parser: 'typescript' })
}
```

### 6.6 `isUpToDate()`

```ts
isUpToDate(): boolean {
  if (!fs.existsSync(this.genFilePath)) return false
  const existing = fs.readFileSync(this.genFilePath, 'utf-8')
  // Compare trimmed to avoid trivial whitespace-only diffs;
  // in practice Prettier output is stable so exact match works.
  return existing.trim() === this.generateContent().trim()
}
```

> **Note:** We compare against `generateContent()` (unformatted) trimmed, not
> `generateFormatted()`, because `generateFormatted()` is async and `isUpToDate()`
> is synchronous. Since Prettier is deterministic and the generated content is
> already structured identically to what Prettier would output, trimmed comparison
> of the raw content is sufficient and correct. The on-disk file is Prettier-formatted
> because that's what we always write; the raw generated content is structured the
> same way. In practice, both the on-disk file and `generateContent()` will produce
> identical output when compared character-for-character because the generator already
> produces Prettier-compatible formatting (trailing commas, sorted keys, etc.).

### 6.7 `write()`

```ts
async write(): Promise<void> {
  const content = await this.generateFormatted()
  if (fs.existsSync(this.genFilePath)) {
    const existing = fs.readFileSync(this.genFilePath, 'utf-8')
    if (existing === content) return // idempotent — no-op
  }
  fs.mkdirSync(path.dirname(this.genFilePath), { recursive: true })
  fs.writeFileSync(this.genFilePath, content)
}
```

### 6.8 `writeCommand()`

```ts
writeCommand(): string {
  return 'pnpm tsx src/tools/markdown-imports-autogen/markdown-import-autogen.ts --mode write'
}
```

### 6.9 CLI argument processing (`markdown-import-autogen.ts`)

```ts
import { cac } from 'cac'
import { getRepositoryRoot } from '@/tests/utils/codebase'
import { getErrorMessage } from '@/types/errors'
import { MarkdownImportsGenerator } from './markdown-import-autogen-lib'
import { autoGenerated } from './markdown-import-autogen'

try {
	const cli = cac('markdown-imports-autogen')
	cli.option('--mode <mode>', '"check" or "write"')
	cli.parse(process.argv)

	const mode = cli.options.mode as string | undefined

	if (!mode || !(mode === 'check' || mode === 'write')) {
		throw new Error('Error: --mode is required and must be "check" or "write"')
	}

	const repoRoot = getRepositoryRoot()
	const generators = Object.entries(autoGenerated).map(([genFile, sourceDir]) => {
		const absGenFile = path.join(repoRoot, genFile.slice(1))
		const absSourceDir = path.join(repoRoot, sourceDir.slice(1))
		return new MarkdownImportsGenerator({
			genFilePath: absGenFile,
			sourceDirs: [absSourceDir],
		})
	})

	// Validate all
	const allErrors: string[] = []
	for (const gen of generators) {
		const errors = gen.validate()
		allErrors.push(...errors.map(e => `${gen.genFileRelativePath()}: ${e}`))
	}

	if (allErrors.length > 0) {
		process.stderr.write(allErrors.join('\n') + '\n')
		process.exit(1)
	}

	if (mode === 'check') {
		const outdated = generators.filter(g => !g.isUpToDate())
		if (outdated.length > 0) {
			const cmd = outdated[0].writeCommand()
			process.stderr.write(
				`The following file(s) are out of date:\n` +
					outdated.map(g => `  ${g.genFileRelativePath()}`).join('\n') +
					`\n\nRun this command to fix:\n  ${cmd}\n`,
			)
			process.exit(1)
		}
		process.stderr.write('All markdown import files are up to date.\n')
		process.exit(0)
	}

	if (mode === 'write') {
		for (const gen of generators) {
			await gen.write()
			const relPath = gen.genFileRelativePath()
			process.stderr.write(`Wrote: ${relPath}\n`)
		}
		process.exit(0)
	}
} catch (error) {
	process.stderr.write(`Error: ${getErrorMessage(error)}\n`)
	process.exit(1)
}
```

```ts
import { describe, expect, it } from 'vitest'

import { MarkdownImportsGenerator } from '@/tools/markdown-imports-autogen/markdown-import-autogen-lib'
import { getRepositoryRoot } from '@/tests/utils/codebase'

const repoRoot = getRepositoryRoot()

describe('markdown-imports-autogen', () => {

	it('passes validation', () => {

			gen.isUpToDate(),

		).toBe(true)
	})

	it('produces valid TypeScript content', () => {
		const content = gen.generateContent()
		// The content must contain the expected structure
		expect(content).toContain('const markdownFiles: Record<')
		expect(content).toContain('export default markdownFiles')
		// Must include all known eligible files
		expect(content).toContain('/resources/docs/features/features.md')
		expect(content).toContain('/resources/docs/contribute/ui/ui.md')
		expect(content).toContain('/resources/docs/questionnaire/software-wallet-questionnaire.md')
	})
})
```

## 9. Edge Cases

| Scenario                                         | Behavior                                                        |
| ------------------------------------------------ | --------------------------------------------------------------- |
| Directory has 0 `.md` files                      | Skipped silently                                                |
| Directory has exactly 1 `.md` file               | Included in output                                              |
| Directory has 2+ `.md` files                     | Validation error with directory path and file names             |
| Non-`.md` files alongside `.md`                  | Ignored for counting; do not affect eligibility                 |
| Symlinks to `.md` files                          | Followed — `fs.readdirSync` follows symlinks by default         |
| Deeply nested `.md` files                        | Each parent directory evaluated independently                   |
| `.md` in root of `sourceDir`                     | Treated the same — root is a directory in the scan              |
| Empty source directory tree                      | Generates `const markdownFiles: Record<...> = {};` — valid file |
| Generated file is already up to date (`--write`) | No write performed (idempotent)                                 |
| Generated file doesn't exist yet (`--check`)     | Reports as out of date                                          |
| Generated file doesn't exist yet (`--write`)     | Created, parent dirs created with `{ recursive: true }`         |

## 12. Constraints and Conventions (from project)

- Use `node:fs` / `node:path` (Node.js built-ins, not external)
- Use `cac` for CLI argument parsing
- Use `prettier.resolveConfig()` + `prettier.format()` for formatting
- Use `getRepositoryRoot()` from `@/tests/utils/codebase` for repo root resolution
- Use `getErrorMessage()` from `@/types/errors` for error handling
- Use `trimWhitespacePrefix()` from `@/types/utils/text` for template literals
- Paths in `autoGenerated` are **repo-root-relative with leading `/`**
- Import alias `@/` maps to `src/` by default; `@/resources/` maps to `resources/`
- Exit code 0 = success, exit code 1 = error / out of date
- All paths use forward slashes (`/`) regardless of platform (already normalized)
