# Icon paint comparison

`icon-paint.ts` observes native Chromium paint under fast scrolling and compares it with slow, settled paint at the same scroll positions. The baseline, parent freeze and pseudo-element freeze each own a browser process. Disposing of each process releases its resources; a stylesheet restoration in a shared context is not an acceptance condition.

A separate discovery process locates the actual row `ViewTimeline` arrival interval. Arrival samples at 35% and 75% must admit opposite actual pseudo-opacity phases (complex dominant and simple dominant), rather than assuming the midpoint covers both fonts. The baseline process captures its first entry before any target visits, actor hides, or frozen styles. Only afterward does it collect three adjacent integer-position references through slow native input. Reference selection uses the blue compositor scroll ruler together with an exact ordinary-flow cyan pixel pattern, never icon similarity. Actual-actor hiding must remove all attributed pixels. Both independent freezes must produce at least three wrong admitted frames.

The report records actual pseudo colors. Colors outside the detector's magenta mask receive an explicit diagnostic color override on those pseudo-elements; this checks geometry and paint synchronization, not production color. The pixel box tolerance remains one pixel and the symmetric silhouette discrepancy limit remains two percent after one-pixel neighbor matching. Clock calibration must be monotonic, with estimated raster pose uncertainty no greater than 0.04 CSS pixels and no disagreement at a known ordinary-flow reference pattern. That uncertainty model assumes locally affine compositor motion and does not establish physical-display subpixel timing.

The `targetArrival` report distinguishes the first captured target pose from its first correct raster. It includes their times relative to input dispatch and acknowledgement, the preceding capture interval, and captured stale target frames. Unobserved arrivals remain null. Input acknowledgement is not a presentation deadline, and capture gaps can include dropped frames. Raster correctness alone does not establish timely arrival.

The observation concerns one first-entry direction and the sampled arrival poses. It establishes neither physical-display FPS nor every intervening fractional pose, browser engine, icon, or animation. A finite capture cannot establish permanent quiescence. The post-slow 400 milliseconds observation wait is explicit; a failure to converge fails the same pixel oracle. Firefox and WebKit require their own native presentation instruments and are not accepted by this `CDP` test.

Failure attachments preserve the source/browser/admission report and every captured PNG, including frames rejected by the instrument and reference hide controls. Reports omit copies of program source and reader implementation. The existing `<h1>` native-motion test remains separate: its native main-thread stall witness and orange pixel masks exercise different behavior; merging those readers would broaden this change without reducing the accepted mechanism.
